# Stack Exchange tag-question projection

The `sx-tag-question` source reads community files from the extracted
`sx-tag-question-parsed.zip` archive. Each nonblank line must contain four
whitespace-separated fields:

```text
user_id tag_id question_id timestamp
```

Only `tag_id` and `question_id` affect the graph. External IDs may be sparse and
are mapped locally to dense temporary IDs. Repeated `(tag_id, question_id)`
records are reduced to one incidence.

## Graph specification

Create a graph specification for one extracted file. The explicit graph name
controls report and cover filenames; it also avoids relying on capitalization
or aliases inferred from an archive filename.

```toml
[graph]
name = "coQuestions-AskUbuntu"
source = "file"
format = "sx-tag-question"
path = "/absolute/path/parsed/askubuntu.txt"
```

Use that graph specification with any construction in the normal way:

```bash
bin/cc_con bpa \
  --graph examples/graphs/stack-exchange-tag-question.toml \
  --run examples/runs/bpa.toml
```

That command uses the small bundled assignment file. For a downloaded
community, copy the graph specification and replace its `path` value.

The reader first builds the distinct tag-question incidence relation. Before
generating any pairs, it prints all prescreen statistics and the ten largest
`tag_id:degree` values to standard error. It does not truncate a large tag.

Each nontrivial tag then generates a clique on its incident questions. A packed
global edge set removes question pairs generated by multiple tags. The tag
lists are released during projection, and neither tag IDs nor native cliques
are passed to a cover construction.

## Native and canonical counts

`question_count` is the number of distinct question IDs in the source file. A
question whose tags occur on no other question is isolated in the projection.
Such questions remain included in source statistics but are removed when the
canonical graph is formed.

The JSON report therefore records both `question_count` and
`canonical_question_count`, plus `isolated_questions_removed`. Top-level graph
`n` equals `canonical_question_count`. The graph consumed by every construction
is simple, undirected, isolate-free, densely numbered, and represented by
sorted duplicate-free adjacency lists.

For tag degrees `d_t`, the prescreen values are

```text
P = sum_t binom(d_t, 2)
potential_CR = 2P / incidence_sum_nontrivial
```

After global edge deduplication, the report adds exact `m`,
`native_cover_size = incidence_sum_nontrivial`, `native_CR = 2m / native_cover_size`,
and `overlap_factor = P / m`. Prescreening indicates pair-generation work but
does not guarantee that the projected graph or its clique-cover construction
will fit in memory.

This reader is independent of the Cornell native-simplex, dual-simplex, and
hyperedge readers. It reads one extracted text file, not the ZIP container
directly.
